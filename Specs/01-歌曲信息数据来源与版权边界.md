# 歌曲信息数据来源与版权边界

**状态：** 已确认（MVP）  
**最后更新：** 2026-07-31  
**适用范围：** 音乐偏好探索 Agent

## 1. 目标与原则

本项目是帮助用户理解和探索音乐的 Agent 应用，不是音乐播放器、歌词站或音乐下载站。

数据方案遵循以下原则：

1. 结构化音乐事实与受版权保护的内容分离处理。
2. 不抓取、不保存、不对外展示来自网易云音乐、QQ 音乐等平台的未授权歌曲内容。
3. 不托管完整音频，不提供下载，也不把完整歌词用于 RAG 或模型输入。
4. 每一条 Agent 输出的关键音乐事实必须保留可追溯来源。
5. 外部服务通过 Provider 适配层接入，以便替换或增加已授权的数据供应商。

## 2. MVP 数据来源决策

| 信息类别 | MVP 来源 | 用途 | 本地保存策略 | 备注 |
| --- | --- | --- | --- | --- |
| 歌手、歌曲、专辑、曲目表、发行信息、创作人员、关系 | MusicBrainz | 音乐实体主库、实体消歧、关系检索 | 保存规范化结构化字段与 MBID | 主数据源 |
| 专辑封面 | Apple iTunes Search API；Cover Art Archive 兜底 | 搜索结果与歌曲卡展示 | 只保存远程 URL、来源和更新时间；不下载到对象存储 | 封面仍受版权保护 |
| 短试听 | Apple iTunes Search API | 用户在探索路线中快速做出选择 | 不保存、不代理、不缓存音频 | 仅在符合 Apple 条款时显示 |
| 完整播放 | 外部平台深链 | 用户自行前往原平台收听 | 仅保存外链 | 不在本项目内播放完整歌曲 |
| 歌词 | 不纳入 MVP | 不展示、不检索、不向量化 | 不保存 | 后续仅可通过取得授权的供应商接入 |
| 音乐背景事实 | 官方艺人/厂牌资料、正式采访、可信媒体、人工审核条目 | Agent 导赏、专辑/流派脉络 | 保存事实摘要、来源 URL、发布时间、审核状态 | 不复制整篇文章 |
| 用户选择与探索进度 | 本项目业务数据库 | 个性化路线、进度与偏好描述 | 用户可查看、导出、删除 | 不推断教育背景等敏感属性 |

## 3. 各来源说明

### 3.1 MusicBrainz：音乐实体底座

MusicBrainz 是开源、社区维护的音乐信息库，适合作为以下实体的规范化来源：

- Artist（艺人）
- Release Group（专辑概念）
- Release（具体发行版）
- Recording（录音版本）
- Track（曲目）
- Work（作品）
- ISRC、创作者、发行时间、地区、标签及实体关系

每个实体优先以 **MBID** 作为内部外部关联锚点。这样可以区分同名歌曲、现场版、Remaster、不同地区版等情况。

**许可。** MusicBrainz 核心数据采用 CC0；补充数据采用 CC BY-NC-SA。MVP 仅将其作为结构化事实来源，并在产品中保留 MusicBrainz 归属信息。

**接口约束。** 线上接口调用必须设置有意义的 `User-Agent`，并遵守每秒不超过一次请求的规则。因此服务端需缓存搜索和详情结果，不能把它作为前端实时直连接口。

### 3.2 Apple iTunes Search API：封面、搜索补充与短试听

Apple iTunes Search API 可返回音乐搜索结果、商店链接、专辑封面，以及部分歌曲的短试听链接。

MVP 的使用边界：

- 封面和试听只能展示在对应歌曲/专辑的导览页面中；
- 试听只允许浏览器直接流式播放，严禁下载、转存、缓存或通过服务器代理；
- 试听卡片需要提供 Apple/iTunes 对应条目的跳转，并使用所需归属标注；
- 当无试听或用户所在地区不可用时，界面降级为封面、元数据和外部收听链接；
- 封面 URL 不写入对象存储，只在数据库中记录远程 URL、供应商及刷新时间。

该 API 是展示层能力，不承担主数据职责；Apple 返回的实体需与 MusicBrainz 实体进行匹配。

### 3.3 Cover Art Archive：封面回退

Cover Art Archive 以 MusicBrainz Release/Release Group 的 MBID 索引封面，适合在 Apple 无可用图片时回退使用。

注意：该服务虽可访问，但封面图片本身的版权不自动开放。MVP 仅远程引用缩略图，记录来源并提供原始条目链接；不批量下载、训练模型或重新分发图片。

### 3.4 音乐背景资料：可引用事实库

音乐入坑教练需要解释“为什么从这首歌进入”“这张专辑在作品序列中的位置”“两个音乐人之间的关联”。此类信息不应由模型自由编造。

来源优先级如下：

1. 艺人官网、唱片公司、音乐节官方介绍；
2. 公开发行的新闻稿、正式访谈；
3. 有署名、可访问原文的可信音乐媒体；
4. 经人工复核后录入的编辑事实。

系统保存的是**短事实摘要**与来源元数据，不保存或展示受版权保护的原文全文。Agent 输出中的重要结论必须能回链到来源。

### 3.5 歌词：明确排除

完整歌词属于高风险版权内容。MVP 不做以下事情：

- 不展示完整歌词或逐行歌词；
- 不从第三方页面爬取歌词；
- 不将歌词写入向量库、知识图谱或 LLM Prompt；
- 不依赖非公开的网易云音乐、QQ 音乐接口。

如未来确实需要歌词能力，应单独采购或签约歌词授权服务，并根据其展示、归属、地域和缓存限制重新评审；不能以技术手段绕过授权。

## 4. 数据模型与来源追踪

所有外部内容都要携带来源记录。建议的核心字段：

```text
music_entity
  id, entity_type, mbid, canonical_name, normalized_name

external_mapping
  id, entity_id, provider, external_id, external_url, match_confidence, refreshed_at

media_asset
  id, entity_id, asset_type, provider, remote_url, attribution, usage_policy, expires_at

knowledge_claim
  id, subject_entity_id, predicate, object_value, summary,
  source_url, source_title, source_type, published_at, reviewed_status
```

其中：

- `external_mapping` 处理 MusicBrainz 与 Apple 等不同供应商的 ID 对齐；
- `media_asset` 明确记录封面/试听的使用限制；
- `knowledge_claim` 是 Agent 可引用的事实最小单元，而不是整篇网页或未经核实的模型回答。

## 5. Agent 使用数据的规则

Agent 只能通过受控工具访问数据：

```text
search_music_entity(query)
get_entity_detail(entity_id)
get_listening_preview(recording_id)
get_verified_claims(entity_id)
build_learning_route(user_goal, available_minutes, preferences)
```

工具返回结果应包含 `source`、`url`、`license_or_usage_note` 和 `confidence`。生成回答时：

- 将“已证实事实”与“基于用户选择的推荐理由”明确区分；
- 没有可靠资料时回答“暂无可靠来源”，不补造创作背景；
- 不将来自 Spotify、Apple、未授权歌词等受限内容输入训练或持久化知识库；
- 用户偏好仅用于路线调整，不用于推断教育背景、心理状态或其他敏感个人属性。

## 6. 不采用的方案

| 方案 | 不采用原因 |
| --- | --- |
| 爬取网易云音乐/QQ 音乐网页或非公开接口 | 授权、稳定性、平台规则与合规风险不可控 |
| 将完整歌词建立 RAG | 版权风险高，且不是 MVP 核心价值 |
| 自建完整歌曲播放/下载 | 需要音乐版权授权，超出项目范围 |
| 将 Spotify 内容喂给模型做训练或持久化知识库 | Spotify 平台政策明确限制此类用途 |
| 把封面下载到自己的对象存储 | 容易造成未经授权的重新分发 |

## 7. 实施顺序

1. 建立 MusicBrainz Provider、实体规范化和 PostgreSQL 缓存；
2. 建立 Apple Provider，并实现封面/试听的合规降级显示；
3. 建立来源追踪数据表与管理端审核流程；
4. 手工录入首批艺人、专辑和流派的可溯源背景事实；
5. 在此基础上实现 Agent 的“研究 → 规划 → 路线生成 → 反馈后重规划”工作流。
