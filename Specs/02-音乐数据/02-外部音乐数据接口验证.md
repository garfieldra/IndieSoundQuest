# 外部音乐数据接口验证

**状态：** 待执行  
**最后更新：** 2026-07-31  
**关联文档：** `01-歌曲信息数据来源与版权边界.md`

## 1. 目的

在接入业务服务前，验证 MVP 选定的外部数据供应商是否能完成以下最小闭环：

```text
用户输入艺人/歌曲名
  → 获取规范化音乐实体
  → 获取可展示的歌曲/专辑信息
  → 可选：得到远程封面 URL 与短试听 URL
```

本验证只检查 API 可达性、响应字段和基本匹配结果；不下载、缓存或存储任何音频、封面或歌词。

## 2. 被验证的供应商

| 供应商 | 请求 | 需要验证的字段 | 通过标准 |
| --- | --- | --- | --- |
| MusicBrainz | Artist Search | `id`（MBID）、`name`、`score` | HTTP 200 且至少有一条艺人结果 |
| MusicBrainz | Release Group Search | `id`、`title` | HTTP 200；能取得该艺人的至少一张专辑概念（Release Group）则记为通过 |
| Cover Art Archive | Release Group Front HEAD | HTTP 状态、最终 URL | 200 代表有可用封面；404 是允许的业务结果，不视为主流程失败 |
| Apple iTunes Search API | Song Search | `trackName`、`artistName`、`collectionName`、`artworkUrl100`、`previewUrl`、`trackViewUrl` | HTTP 200 且至少有一条歌曲结果；`previewUrl` 允许为空 |

## 3. 验证脚本

脚本位置：`Demos/verify_music_providers.py`

运行方式：

```bash
cd /Users/wangrui/Documents/Projects/music-agent
python3 -m pip install -r Demos/requirements.txt
python3 Demos/verify_music_providers.py
```

可选参数：

```bash
python3 Demos/verify_music_providers.py --artist 五月天 --song 温柔 --country US
```

参数说明：

- `--artist`：用于 MusicBrainz 艺人/发行版检索，也用于 Apple 搜索；默认 `五月天`。
- `--song`：用于展示查询意图；默认 `温柔`。
- `--country`：Apple Store 的双字母地区代码；默认 `US`。不同地区的返回曲目和试听可用性可能不同。
- `--timeout`：单个 HTTP 请求的超时秒数；默认 `15`。

脚本仅依赖 `httpx`，依赖版本写在 `Demos/requirements.txt`；不需要 API Key。之所以不使用 Python 标准库 `urllib`，是因为首次实测中该客户端与当前环境的 MusicBrainz TLS 连接出现间歇性 EOF，而 `httpx` 可稳定完成同一 HTTPS 请求。

## 4. 脚本行为与边界

1. 每个 MusicBrainz 请求均带项目名称、版本和联系地址格式的 `User-Agent`。
2. MusicBrainz 请求之间至少等待 1.1 秒，以满足不超过每秒一次请求的限制。
3. Apple 返回的封面与试听只读取 URL 和字段是否存在；脚本不会请求音频内容，也不会下载图片。
4. Cover Art Archive 仅发送 `HEAD` 请求；`404` 表示该发行组没有可用封面，是预期的降级分支。
5. 脚本在标准输出打印 JSON 报告，不写入项目数据库，不产生缓存文件。
6. 对网络/TLS 级瞬时故障，MusicBrainz 最多在限速后重试一次；HTTP 429/503 不重试，以避免重试风暴。网络、地区限制、限流和供应商临时故障必须被记录为结构化失败信息，不应导致脚本崩溃。

## 5. 结果判定

| 情况 | 判定 | 后续动作 |
| --- | --- | --- |
| MusicBrainz 艺人和 Apple 搜索均成功 | 基础闭环通过 | 可以进入 Provider 接口设计 |
| MusicBrainz 成功，Apple 无结果/不可达 | 部分通过 | UI 采用外链与无试听降级；检查地区与网络 |
| Apple 成功，MusicBrainz 无结果 | 部分通过 | 记录实体对齐缺口，不以 Apple ID 作为长期主键 |
| CAA 404 | 通过（可降级） | 用 Apple 封面或默认占位图 |
| Apple `previewUrl` 为空 | 通过（可降级） | 展示外部收听链接，不提供站内短试听 |
| 任一服务 429/503 | 不做重试风暴 | 记录供应商限流，后续 Provider 层增加退避和缓存 |

结果摘要：

| 检查项 | 结果 | 观察 |
| --- | --- | --- |
| MusicBrainz Artist Search | 通过 | 返回五月天，MBID 为 `e73ed332-bbde-4d69-87a9-250627ae0e29`，匹配分数 100 |

结论：MVP 的主数据（MusicBrainz）和展示/试听补充（Apple）已完成真实接口验证。首版可以以 Apple 封面为优先来源、默认占位图为最终降级；Cover Art Archive 继续保留为 Provider，但在正式部署环境重新验证后再启用。

补充：首次实现使用 Python 标准库 `urllib` 时，MusicBrainz 也出现过间歇性 TLS EOF。使用 `httpx` 后 MusicBrainz 查询稳定通过，因此 Demo 显式依赖 `httpx`。
