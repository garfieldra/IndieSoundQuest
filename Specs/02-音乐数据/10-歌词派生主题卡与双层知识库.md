# 歌词派生主题卡与双层知识库

> 状态：首批已完成（834 张主题卡已审核并导入本地 Milvus）  
> 版本：v1.0  
> 前置规格：`09-Milvus知识库与事实治理规格.md`、`14-候选歌曲Agent证据驱动探索与质量闸门.md`

## 1. 目标

将本地歌词资料转为不含歌词原文的“歌曲主题卡”，用于离线实验和后续候选歌曲 Agent 的语义召回。首批来源是 `LyricMind/data` 的 836 篇结构化 Markdown；`ChineseLyrics` 的十万级数据仅作为后续离线扩容候选。

主题卡不是歌词镜像、不是歌词搜索服务，也不能向用户展示或反向还原原文。

## 2. 双层数据边界

| 层级 | 数据 | 用途 | 可部署性 |
| --- | --- | --- | --- |
| `EXPERIMENTAL_LYRIC_DERIVED` | 从本地歌词生成的主题、情绪、场景等派生字段 | 离线评测、人工审查 | 默认不可进入线上检索 |
| `LOCAL_CURATED` | 经维护者审核清单批准、且无歌词原文的主题卡 | 线上 Milvus 知识召回 | 可部署 |

不保存或写入 Milvus：完整歌词、连续歌词片段、音频、逐句 embedding、可重建歌词的摘要。

## 3. 主题卡 Schema

```json
{
  "schemaVersion": "1.0",
  "title": "南国的孩子",
  "artist": "张悬",
  "album": "城市",
  "releaseYear": 2009,
  "region": "台湾",
  "themes": ["流浪与自由", "成长中的自我寻找"],
  "moods": ["辽阔", "炽热", "感伤"],
  "scenes": ["独自远行", "夜晚望向远方"],
  "narrativePerspective": "第三人称凝望",
  "summary": "不超过 120 字的非引文主题概述",
  "sourceType": "EXPERIMENTAL_LYRIC_DERIVED",
  "reviewStatus": "PENDING_REVIEW",
  "sourceFingerprint": "sha256..."
}
```

`summary` 不得出现连续歌词原句；抽取器会在输出前做启发式检测，并保留输入指纹而非歌词正文。

## 4. 流程

```text
LyricMind Markdown
  → 解析元数据与歌词（仅运行时使用）
  → LLM 结构化主题提取
  → 原文泄漏检查 / Schema 校验
  → JSONL 实验主题卡
  → 人工抽检与改写
  → LOCAL_CURATED
  → Milvus
```

首轮仅对 `LyricMind/data` 运行；先抽取小样本，再人工检查标签与摘要质量后才扩展到 836 首。`ChineseLyrics` 必须另行设计流式处理、去重、实体匹配、成本预算和抽检方案，不能直接整库导入。

## 5. 验收

- [ ] 抽取器可按艺人、数量与断点续跑执行；
- [ ] 输出 JSONL 不包含 `lyrics` 字段；
- [ ] 每张卡通过 Schema、长度和原文泄漏检查；
- [ ] 同一“艺人 + 歌名”仅保留一张主题卡；同名不同版本须待后续引入版本字段后才可并存；
- [ ] 小样本经过人工审核后才进入 `LOCAL_CURATED`；
- [ ] 实验卡不会被线上候选 Agent 或 Milvus 正式集合读取。

## 6. 实现工具

- `Demos/extract_lyric_theme_cards.py`：从 LyricMind Markdown 断点续跑生成实验卡；
- `Demos/audit_lyric_theme_cards.py`：检查 Schema、重复、原文禁止字段与标签长度；
- `Demos/promote_reviewed_theme_cards.py`：仅根据人工提供的 `sourceFingerprint` 白名单提升为 `LOCAL_CURATED`。
- `Demos/build_theme_card_approval_manifest.py`：将结构审计、内容边界检查及维护者分层抽样审核的结果固化为可追溯批准清单。

## 7. 向量化实现

- 正式 Milvus 集合只接收同时为 `LOCAL_CURATED` 与 `APPROVED` 的主题卡；没有审核数据时导入脚本必须零写入退出。
- 嵌入模型使用 `BAAI/bge-small-zh-v1.5`，通过 FastEmbed 的 CPU/ONNX 运行时调用；模型文件在首次真实检索或导入时下载，不作为 Docker 构建依赖。
- 嵌入输入仅由歌曲名、艺人、主题、情绪、场景、叙事视角和主题概述拼接而成，明确排除歌词正文和本地源文件路径。
- Agent 容器将 embedding 模型缓存在独立 Docker volume；首次导入下载模型，后续检索不会重复下载。
