# 音乐实体关系、百科语境与听众相似性工具规格

状态：已实现并验收（Last.fm 实时调用待配置 API Key）

## 1. 目标

在不新增业务 Agent、不引入固定研究流水线的前提下，为统一音乐探索 Agent 增加三类可自主选择的原子研究工具：

1. MusicBrainz 作品版本、署名和实体关系研究；
2. Wikidata / Wikipedia 艺人身份与音乐史语境研究；
3. Last.fm 相似歌曲、相似艺人与听众标签发现。

沙箱和任意 CLI 执行不属于本期范围。

## 2. 总体边界

- 三类能力只作为统一 ReAct Agent 的可选 Tool，不规定固定调用顺序。
- MusicBrainz 是规范身份、发行版本和结构化署名事实来源，不负责主观评价。
- Wikimedia 是百科实体与历史语境来源；重要幕后事实仍应由访谈、正式 Credits 或独立来源交叉支持。
- Last.fm 只提供听众相似性、标签和热度信号，不能成为歌曲身份或创作事实的权威来源。
- Last.fm 发现的具体歌曲进入推荐或候选池前，仍必须由 MusicBrainz 核验。
- 本地 Milvus 仍是解释增强，不参与限制在线发现范围。
- 工具失败返回空结果和可观测降级状态，不阻断 Agent 使用其他来源继续工作。

## 3. 工具契约

### 3.1 `research_musicbrainz`

输入：

- `query`：精确的艺人、作品或专辑检索文本；
- `entityType`：`artist | recording | release-group | work`；
- `entityMbid`：可选；已完成身份解析时优先使用。
- `artistName` 与 `title`：没有 MBID 时分别传递，不允许把自由文本搜索排名直接当成正确身份。

输出为有界的规范化来源：实体 MBID、别名、流派/标签、ISRC、艺人署名、发行版本及关系。Java 服务统一负责 MusicBrainz 调用、礼貌限流、重试与 Redis Provider 缓存；Python Agent 不直连数据库。

搜索结果存在接近候选时返回歧义来源，不静默把低置信度候选当成确定实体。

### 3.2 `search_wikimedia`

输入为自然语言查询，最多返回八条去重结果。工具并发查询：

- Wikipedia 简介和原始页面链接；
- Wikidata 实体 ID、标签与描述。

所有请求使用明确的项目 User-Agent、固定 HTTPS 官方域名和有界超时，不接受模型指定任意 API 地址。

### 3.3 `search_lastfm`

输入：

- `artistName`；
- 可选 `trackTitle`；
- `mode`：`similar_artists | top_tracks | artist_tags | similar_tracks | track_tags`。

服务端持有 `LASTFM_API_KEY`，不得写入日志、SSE、模型上下文或卡片。未配置 Key 时工具声明为不可用，Supervisor 改用公开网络资料，不循环重试。

## 4. Agent 决策与证据

Supervisor 每轮只能选择一个动作，并根据问题与证据缺口自行决定是否调用：

- 版本、ISRC、署名、发行和关系问题优先考虑 MusicBrainz；
- 身份、别名、成员、地区、年代与历史语境优先考虑 Wikimedia；
- 相似性、标签、热门作品与探索扩散可以考虑 Last.fm；
- 创作背景、采访和制作过程仍需网络搜索与安全正文精读。

三类结果统一进入现有 `web_sources`、证据覆盖评估、Claim 语义审校和持久化来源卡。来源类型必须保留，模型不得把听众标签改写为创作者事实。

## 5. 配置

```dotenv
LASTFM_API_KEY=
WIKIMEDIA_RESEARCH_ENABLED=true
```

MusicBrainz 和 Wikimedia 不需要新增用户账号凭证。Last.fm 未配置时，其余能力必须正常启动并通过健康检查。

## 6. 验收标准

1. Java 内部接口可以按实体类型返回有界 MusicBrainz 关系投影，并拒绝非法类型或非法 MBID。
2. Wikimedia 工具可以返回 Wikipedia 与 Wikidata 的可点击、去重来源。
3. Last.fm 五种模式能被解析为标准来源；未配置 Key 时零网络调用、安全降级。
4. ReAct 决策器可自主选择三类动作，且公开计划、工具事件和 trace 可观察。
5. 深度分析卡能识别结构化目录、百科资料和听众相似性三种来源强度。
6. Python、Java、前端测试和 Docker 构建通过；真实联调中单一来源失败不影响最终回答。

## 7. 实现与验收记录

- `research_musicbrainz` 已通过 Java 内部边界接入；自由检索使用分离的艺人/曲名约束，近似版本返回歧义，不再把同名异艺人作品静默选中。
- 已真实核验张悬《寶貝 (In a Day)》录音实体，能够返回发行日期、ISRC、发行版本，以及制作、录音、演唱、乐器与作品关系。
- `search_wikimedia` 已真实返回 Wikipedia 与 Wikidata 两类来源。
- `search_lastfm` 的五种模式、结果规范化和无 Key 降级已通过自动化测试；本地 `LASTFM_API_KEY` 已通过被 Git 忽略的 `.env` 注入 Agent Service 与 Worker，未写入 Spec、示例配置、日志、SSE 或模型上下文。
- 真实只读联调已通过：`artist.getSimilar`、`artist.getTopTracks`、`artist.getTopTags` 与已知曲目的 `track.getSimilar` 均能返回标准化 Last.fm 来源。个别中文曲目无相似结果时按来源覆盖不足降级，不把空结果误判为鉴权失败，也不阻断 Agent 改用网络搜索、MusicBrainz 或 Wikimedia。
- 统一 Agent 的真实创作背景分析已完成：取得 8 个公开来源、2 个正文来源和 8 个独立域名，生成 1793 字分析，并语义审校 10 条 Claim。
- DeepSeek 较大结构化审校偶发不兼容时，会自动回退到普通 JSON 响应并继续执行同一 Pydantic Schema 校验；未通过校验的输出仍不会落库。
