# Agent 自适应研究、实体解析与偏好推理规格

## 1. 目标

统一音乐探索 Agent 必须具备三项可复用的核心能力：

1. 把自然语言请求转换为带完成条件的音乐研究目标，并在工具返回后根据证据缺口滚动调整计划；
2. 对艺人名称、艺名、本名、繁简体和同名实体进行统一解析，必要时通过可恢复澄清中断交由用户确认；
3. 从用户原话和会话上下文中提取多维音乐偏好，用于搜索切面、结果排序和可解释推荐。

该能力同时服务普通音乐推荐、候选池构建与报告撰写，不新增对外 Agent。世界杯仍是可选 Skill。

## 2. 非目标

- 不把研究过程固化为固定工具调用顺序；
- 不要求每次请求都搜索所有数据源；
- 不将模型推断的人格、教育背景或音乐偏好直接写入长期档案；
- 不以本地目录或 Milvus 覆盖范围限制在线发现；
- 不向用户展示隐藏思维链，只展示任务计划、工具摘要、证据缺口与结果。

## 3. 运行时工作记忆

每次 Agent Run 在 LangGraph 状态中维护：

- `preferenceProfile`：本轮结构化偏好画像；
- `entityResolutions`：字面艺人、规范名称、MusicBrainz MBID、置信度及候选；
- `researchAssessment`：当前来源数量、各明确艺人覆盖情况、证据缺口和是否达到进入生成阶段的最低条件；
- `searchAttempts`：本轮网络研究次数；
- `actionHistory`：用户可见的滚动计划依据。

这些字段属于单次运行工作记忆。只有最终可展示摘要、卡片与用户反馈进入持久化层。

## 4. 结构化音乐偏好

`preferenceProfile` 至少包含：

- 明确艺人；
- 流派与声音特征；
- 情绪；
- 聆听场景；
- 语言或地域；
- 年代；
- 歌词主题与创作语境；
- 熟悉度倾向（代表作、进阶曲目、冷门探索或混合）；
- 排除项；
- 建议搜索切面；
- 对应的用户原文证据。

模型可以从已知艺人推断相邻声音方向，但推断项必须与用户原文事实区分，不得冒充用户明确表达。

## 5. 实体解析与必要澄清

1. 从当前消息中提取字面艺人，不得仅依赖“我喜欢……”句式；
2. 使用 MusicBrainz 搜索名称与 alias；
3. 高置信且领先候选明显时自动采用规范身份；
4. 同一 MBID 的艺名、本名和繁简写法合并为同一实体；
5. 两个或更多高分候选接近、且选择会改变搜索范围时，生成 `GENERAL_CLARIFICATION` 卡并把 Agent Run 置为 `WAITING_FOR_USER`；
6. 无结果不等于有歧义。Agent 可以继续在线搜索，只有无法安全确定身份且结果依赖该身份时才阻塞。

## 6. 自适应研究与滚动计划

Supervisor 根据偏好画像、实体解析和当前证据自主选择搜索、知识补充、推荐、澄清或回答。

网络搜索后必须生成 `researchAssessment`：

- 明确艺人的独立搜索是否均获得资料；
- 是否存在只有艺人关系而无具体歌曲的缺口；
- 开放场景请求是否拥有足够多样的搜索切面；
- 当前资料是否足以支持用户要求的输出数量；
- 下一次搜索应针对哪些缺口。

如果明显缺口仍存在且预算允许，Supervisor 必须获得继续搜索的机会；不得因已经调用过一次网络工具而强制进入生成。最多进行三轮有新增目标的网络研究，重复且无收益的查询应提前停止。

## 7. 推荐质量契约

- 明确单艺人并要求“几首歌曲”：最终至少给出 3 首已核验歌曲；
- 明确多艺人：推荐结果应覆盖最多 5 个实际艺人身份，艺名别名不得重复计数；
- 场景、情绪或流派请求：结果必须能映射到画像中的至少两个有效维度；
- 推荐理由需要说明声音、情绪、文本、场景或创作脉络上的关系；
- 网络负责发现，MusicBrainz 负责身份核验；目录浏览顺序不得被当作热门度排序。

## 8. 可观测性与前端计划

SSE 计划允许展示：

- 正在理解哪些音乐偏好；
- 正在核验哪些艺人身份；
- 当前正在补足哪个证据缺口；
- 搜索计划为何发生调整；
- 已覆盖多少个明确目标。

不得展示模型隐藏思维链、完整 Prompt、密钥、内部地址或未经整理的工具响应。

## 9. 验收

至少覆盖以下真实端到端场景：

1. `给我推荐几首 Asen 的歌曲`：识别目标身份并返回不少于 3 首具体歌曲；
2. 多艺人并列推荐：不允许单一搜索结果挤占全部结果；
3. `适合深夜写代码、克制但有节奏感的音乐`：能形成情绪、场景和声音维度并据此推荐；
4. 同名或高相似艺人：仅在选择确实影响结果时进入可恢复澄清；
5. 工具部分失败：保留已有证据，调整计划或明确降级，不伪造完成状态。
