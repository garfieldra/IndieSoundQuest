# 音乐探索 Agent 运行时与自主决策架构

- 状态：已实现首版
- 范围：对话入口、候选池 Agent、报告 Agent

## 目标与边界

系统只保留候选歌曲池生成 Agent 与赛后报告 Agent 两个业务 Agent。对话路由、研究任务和核验任务是技术运行时组件，不作为第三个业务 Agent。用户通过多轮对话表达艺人、歌曲、专辑、风格、场景、情绪、年代、语言或文化语境，运行时自主决定继续回答、必要澄清、调用资料工具或展示歌曲世界杯入口。

## 自主决策

不得将 Agent 写成固定的“解析—搜索—核验—入池”流水线。每轮由 Supervisor 根据当前状态、观察、预算和用户约束选择一个 Action；护栏只用于契约、安全、预算、去重与无收益循环阻断。

对话 Action 为 `search_web`、`search_knowledge`、`clarify`、`propose_tournament`、`respond`。候选 Agent 保留意图理解、实体解析、网络发现、MusicBrainz 核验、目录规范化、重排和提交等 ReAct Action。

## 数据源

- 网络搜索负责主要发现；中文查询优先博查，其他查询可使用 Tavily。
- MusicBrainz 负责艺人和歌曲身份核验。
- Java 目录负责规范化落库、去重和赛事引用。
- Milvus 只补充歌词主题、文化语境和推荐理由，不限制候选发现。
- 不设置网络/本地硬比例；本地结果不相关时允许为零。

## 状态、恢复与卡片

每次用户消息拥有独立 `agentRunId`，LangGraph 使用它保存运行内 checkpoint；Java 持久化用户消息、Agent Run、Agent 回复和结构化卡片。SSE 中断后，客户端重新读取消息即可恢复已完成产物。

Agent 可返回 `cardIntent`，Java 只接受白名单卡片并持久化。前端不得在每轮回复后自行猜测和创建世界杯卡片。

## 可解释轨迹

只流式输出安全行动摘要、滚动计划、工具名称、数量与耗时；不输出思维链、系统 Prompt、内部 URL、密钥或隐藏评分。最终结果出现后默认折叠。

## 在线目录吞吐约束

- 已通过 MusicBrainz 解析的艺人使用 recording browse 批量获取规范曲目，不再把每首歌拆成一次搜索请求。
- 32 首赛事一次准备 32 首主池与 32 首补位池；外部依赖健康时，候选生成应在 180 秒内完成。
- Agent 可以自主改写检索计划，但已有足量规范候选时不得继续无收益的逐曲网页核验；这属于完成契约护栏，不是固定工作流。
- 继续遵守 MusicBrainz 公共服务限速；性能提升依靠批量接口、缓存复用与减少重复调用，不突破上游限流。

## 验收

- 普通音乐问答不会无条件产生世界杯卡片。
- 明确偏好时 Agent 可以自主产生持久化启动卡。
- 历史启动卡保留原始偏好并能重新进入候选确认。
- 计划由真实 Action 驱动。
- Java、Agent、Web 构建和 SSE 真实联调通过。
