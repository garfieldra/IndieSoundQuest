# 赛事过程信号与报告推理

**状态：** 已确认 v1.0  
**前置规格：** `05-赛后偏好报告与长图.md`、`07-报告Agent子Agent与证据链.md`

## 1. 目标

赛后报告不仅依据冠军和最终名次，还必须分析用户在每一轮中“更偏爱 A 而非 B”的取舍。报告要解释偏好如何形成，而非把冠军当作唯一证据。

该能力只服务于既有赛后报告 Agent，不新增第三个业务 Agent。主 Agent 和子 Agent 仍采用 ReAct 自主决策；本规格定义可用事实、输出契约与安全约束，不规定固定调用步骤。

## 2. 赛事过程事实

Java 赛事快照补充或明确以下只读字段：

```json
{
  "entries": [{"entryId":"…","recordingId":"…","title":"…","artistName":"…"}],
  "matches": [{
    "matchId":"…",
    "roundNumber":1,
    "matchIndex":0,
    "leftEntryId":"…",
    "rightEntryId":"…",
    "winnerEntryId":"…"
  }]
}
```

Java 不解释音乐风格，也不推断偏好；它只保证对局顺序、双方、胜者与赛事归属准确且不可变。

## 3. Agent 推理信号

偏好分析子 Agent 可从以下信号归纳假设：

| 信号 | 含义 | 使用限制 |
| --- | --- | --- |
| 冠军/四强/八强 | 稳定强偏好锚点 | 不能单独证明某个抽象维度 |
| 单场胜负 | 某次明确取舍 | 一场仅作低至中置信证据 |
| 相近对局 | 两首在主题、风格或语境上相近时的取舍 | 优先用于解释“偏好边界” |
| 晋级路径 | 同一作品连续胜出过程 | 可提高稳定性判断 |
| 关键失利作品 | 高轮次被淘汰但仍具吸引力的作品 | 用于推荐的邻近边界 |

“相近”只能由规范元数据、已审主题卡或来源明确的网络资料支持；模型不能凭记忆给作品添加事实。

## 4. 过程证据卡

Agent 输出内部 `match_fact` 证据卡，供维度、摘要和推荐理由引用：

```json
{
  "kind": "match_fact",
  "matchId": "uuid",
  "roundNumber": 3,
  "winner": {"recordingId":"uuid","title":"…","artistName":"…"},
  "loser": {"recordingId":"uuid","title":"…","artistName":"…"},
  "signalRole": "preference_boundary | stable_anchor | near_finalist",
  "derivedNote": "仅基于本场取舍的谨慎归纳"
}
```

前端只展示双方歌曲、轮次和简短自然语言说明，不展示 UUID、模型分数、Prompt 或隐藏推理。

## 5. 报告呈现

报告新增“你的选择轨迹”段落：

- 选择 3–5 个最具信息量的对局；
- 至少包含一个冠军晋级相关对局与一个偏好边界对局（若赛事事实足够）；
- 采用“你在本场更偏向……”而非“这首歌更好”；
- 每个偏好维度至少引用一条赛事过程事实或明确说明其为弱推断；
- 推荐理由优先关联某一类重复出现的取舍，而不是泛用模板。

## 6. 安全与降级

- 不从单次投票推断人格、心理状态、教育、职业或现实身份；
- 对局不足、赛事数据缺失时，降级为冠军与最终名次分析，并标记“过程信号不足”；
- 网络资料只能解释歌曲/艺人背景，不能改写胜负事实；
- Critic 必须检查引用的 `matchId`、双方和胜者是否与 Java 快照一致。

## 7. 验收标准

- [ ] 16 与 32 首赛事均能输出完整对局树；
- [ ] 报告至少引用 3 条真实过程信号，且不错误归属胜负双方；
- [ ] 推荐理由至少有一条关联过程中的重复取舍；
- [ ] 过程数据缺失时可结构化降级；
- [ ] Critic 能拦截虚构对局、错误胜者和确定性人格推断。
