# 研究信源卡片展示

- 状态：已实现
- 优先级：P2
- 依赖：`23-候选歌曲证据模型与质量控制.md`、`26-国内内容研究工具接入.md`

## 目标

让用户能够一眼区分推荐或候选歌曲背后的资料来自知乎、豆瓣、B 站或一般公开网页；保留证据的可访问性，但不把页面变成资讯流。

## 展示规则

1. 网络发现的报告推荐继续显示“网络发现 · 待核验”，并在下方展示一个可点击的来源卡片；
2. 候选确认页的“探索依据”折叠区同样以紧凑来源卡片呈现已返回的证据；
3. 根据 URL 域名在前端确定展示类别，不信任模型自由生成的平台名：

| 域名 | 卡片标题 | 内容类型 |
| --- | --- | --- |
| `open.spotify.com` | Spotify | 目录资料 |
| `zhihu.com` | 知乎 | 讨论 / 文章 |
| `douban.com` | 豆瓣 | 音乐资料 |
| `bilibili.com`、`b23.tv` | 哔哩哔哩 | 视频资料 |
| `xiaohongshu.com`、`xhslink.com` | 公开网页 | 社区线索 |
| `musicbrainz.org` | MusicBrainz | 音乐资料库 |
| 其他有效 URL | 公开网页 | 参考资料 |

4. 每张卡只展示来源、简短类型、标题及“查看”动作；不展示完整正文、作者个人资料、Cookie、内部研究轨迹或可信度分数；
5. 链接在新标签页打开，使用 `rel="noreferrer noopener"`；无法解析的 URL 降级为“公开网页”。

## 视觉约束

- 沿用暖白唱片内页的细边框、低饱和色与宋体感字形；
- 使用中文单字或简短字母印记（知 / 豆 / B / 网 / MB），不依赖第三方 Logo、品牌图片或 emoji；
- 平台色只用于左侧细线和圆形印记，不能压过歌曲、艺人和推荐理由；
- 长图导出仍保持紧凑文字摘要，不额外嵌入外部信源卡，避免长图失控和链接失效预期。

## 验收

- 知乎、豆瓣、B 站、普通网页 URL 分别渲染对应平台文字与视觉变体；
- 候选卡内证据不再嵌套在试听按钮中，键盘操作与外链点击正常；
- 未知或异常 URL 不导致页面崩溃，安全使用通用卡；
- 前端 TypeScript 构建通过。
