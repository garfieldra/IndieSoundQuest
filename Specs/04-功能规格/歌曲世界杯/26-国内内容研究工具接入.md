# 国内内容研究工具接入

- 状态：阶段 A（知乎官方开放平台）已实现并验证；阶段 B（B 站、豆瓣）已实现并验证；两个业务 Agent 已接入可选研究工具
- 优先级：P1
- 依赖：`15-报告Agent网络发现优先与Milvus增强.md`、`16-在线优先候选发现与意图澄清.md`、`23-候选歌曲证据模型与质量控制.md`

## 1. 目标

为现有两个业务 Agent 增加可控的中文内容研究能力：

1. 候选歌曲池 Agent 可从高质量中文内容中发现明确的“歌曲名 + 艺人”线索，后续仍必须由 MusicBrainz 核验；
2. 赛后报告 Agent 可补充乐评、访谈、创作语境与文化讨论，并将来源以可点击摘要展示给用户；
3. 不增加第三个业务 Agent，不把任何平台的搜索结果、用户观点或模型记忆当作歌曲实体或赛事事实。

首期纳入知乎、B 站、豆瓣。小红书只接受现有通用搜索已返回的公开链接；不进行登录、浏览器自动化或平台专属抓取。

## 2. 平台与边界

| 平台 | 首期能力 | 运行方式 | 不允许的能力 |
| --- | --- | --- | --- |
| 知乎 | 搜索问题/回答/文章 | 官方 `zhihu-cli` 只读 sidecar（开放平台 Access Secret） | 发布、点赞、关注、通知、收藏、Cookie、账号密码或凭证写入模型上下文 |
| B 站 | 关键词搜索视频；读取视频标题、UP 主、简介、标签、公开字幕摘要 | 受控 B 站 MCP/REST sidecar | 登录账号操作、投稿、互动、批量评论、完整弹幕/评论抓取、媒体下载 |
| 豆瓣 | 搜索音乐条目、专辑、音乐人和豆列；读取条目摘要与公开 URL | `douban-cli` lookup-only sidecar | mirror、离线全量同步、批量爬取原始页面、用户账号功能 |
| 小红书 | 从通用 Web Search 已发现的公开链接中保留标题/URL | 现有 `WebSearchTool` | 直接平台搜索、扫码登录、Cookie 持久化、Playwright 自动化、发布与互动 |

非营利或个人项目不构成绕过平台条款、访问控制或技术限制的授权。所有适配器只访问其自身允许的公开读取面，并在平台策略、可用性或访问控制变化时立即降级。

## 3. 架构与授权模型

```text
Candidate Pool Agent / Report Agent (ReAct Supervisor)
                  │ 自主决定是否研究、选哪个平台、何时停止
                  ▼
       DomesticContentResearchTool（Python 统一契约）
       ├── ZhihuResearchAdapter → zhihu-research sidecar → 官方 zhihu-cli → 开放平台 Search API
       ├── BilibiliResearchAdapter → bilibili-research sidecar → MCP/受控 REST
       ├── DoubanResearchAdapter → douban-research sidecar → douban CLI/HTTP
       └── WebSearchTool → 已索引的小红书公开链接（无专属登录）
                  ▼
          受限 ResearchSource / SongHint / EvidenceRef
```

- `DomesticContentResearchTool` 是两个业务 Agent 的内部工具集合，不是新 Agent；
- ReAct Supervisor 根据用户问题、已有证据密度、平台适配性、预算与剩余时间自主决定是否调用和调用哪一个；不得变成“知乎 → B 站 → 豆瓣”的固定流水线；
- 所有 sidecar 仅加入 Docker 内部网络，不暴露宿主机端口；Agent 仅调用本项目受控的适配器 API，不直接执行任意 CLI 命令或 MCP 工具；
- 适配器采用每平台独立超时、并发上限、查询去重与熔断。某个平台失败只生成受控降级事件，不能阻断候选池或报告。

### 3.1 知乎开放平台凭证

- 使用知乎开放平台 `Access Secret` 的 Bearer 鉴权与秒级 `X-Request-Timestamp`，不使用二维码、Cookie、账号密码或浏览器自动化；
- 凭证只注入 `zhihu-research` sidecar 的运行环境；Java、Agent、Milvus、前端、SSE、日志和模型上下文都无法读取该值；
- 本地开发放在已忽略的 `.env`，部署使用 Secret Store；`.env.example` 只保留空占位；
- sidecar 健康检查只暴露 `configured: true|false` 与 `authMode: OPEN_PLATFORM`，不返回账号、凭证或其摘要；
- 鉴权失败、限流或上游不可用时，分别返回受控 `PLATFORM_AUTH_REQUIRED`、`PLATFORM_RATE_LIMITED` 或 `PLATFORM_UNAVAILABLE`，调用方降级到其他研究工具。

启用步骤（仅在需要知乎资料时执行）：

```bash
# 由部署 Secret Store 或受控环境注入 ZHIHU_ACCESS_SECRET，并设置 ZHIHU_RESEARCH_ENABLED=true。
docker compose --env-file .env -f infra/compose.yaml --profile domestic-research up -d zhihu-research agent-service
```

## 4. 统一研究结果契约

所有平台适配器必须返回相同的受限对象，正文不入库、不传模型：

```json
{
  "provider": "ZHIHU | BILIBILI | DOUBAN | XIAOHONGSHU_PUBLIC_LINK",
  "sourceType": "ANSWER | ARTICLE | VIDEO | VIDEO_TRANSCRIPT | MUSIC_SUBJECT | DOULIST | PUBLIC_LINK",
  "sourceUrl": "https://...",
  "title": "最长 180 字",
  "authorDisplayName": "可空，最长 80 字",
  "publishedAt": "可空 ISO-8601",
  "snippet": "最多 280 字、仅与查询相关的公开摘录",
  "queryPurpose": "candidate_discovery | cultural_context | recommendation_validation",
  "retrievedAt": "ISO-8601",
  "contentConfidence": "LOW | MEDIUM",
  "platformMetadata": {"仅白名单字段": "..."}
}
```

规则：

- `snippet` 由适配器截断、去 HTML、去脚本、去联系方式与账号标识后返回；
- 不保留完整网页、完整回答、完整字幕、评论、弹幕、Cookie、请求头、内部 MCP 输出或平台原始 JSON；
- `sourceUrl` 必须为 `https` 公网 URL，域名需与 provider 白名单一致；
- 同一 `provider + sourceUrl` 在单次 run 内只保留一次；
- 公开平台内容默认是线索或语境证据，不能单独支撑歌词含义、创作背景等事实性断言；这类结论应保守措辞或与官方/编辑来源交叉验证。

## 5. 两个 Agent 的使用边界

### 5.1 候选歌曲池 Agent

- 允许将平台内容用于发现明确出现的 `title + artistName` 对；每一对仍必须附 URL + 8–200 字原文片段，并送入 MusicBrainz 对齐；
- B 站视频标题/简介、知乎回答、豆列仅是 `DISCOVERY_HINT`，在 MusicBrainz 成功且 Java 目录导入后才是可参赛 `Recording`；
- 小红书公开链接仅能作为弱线索，首期不单独驱动歌曲导入；
- 任何平台不足、失效或无可核验线索时，Agent 自主改用现有 Web Search/MusicBrainz/目录能力，不降低赛事的“等量主池 + 补位”门槛。

### 5.2 赛后报告 Agent

- 可引用 `ResearchSource` 支撑“可继续探索的方向”“作品被怎样讨论”等推荐性表达；
- 赛事胜负、选择轨迹、偏好信号始终以 Java 的赛事事实快照为唯一事实来源；
- 生成推荐卡时展示 `来源标题 + 平台标签 + 链接`，不展示评分、完整摘录或内部研究步骤；
- 研究来源无法核验或超时，报告仍可仅依据赛事事实和已有公开 Web 来源完成。

## 6. Sidecar API 与配置

各 sidecar 对 Agent 只暴露最小 REST 契约：

```http
GET /health
POST /v1/research/search
{
  "query": "string (2–240)",
  "purpose": "candidate_discovery | cultural_context | recommendation_validation",
  "limit": 1..8
}
```

响应为 `ResearchSource[]` 或受控错误码。B 站可额外提供 `POST /v1/research/video-detail`，但只接收已经由 search 返回的 `bvid`。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `ZHIHU_RESEARCH_ENABLED` | `false` | 明确开启后才注册知乎开放平台工具 |
| `ZHIHU_ACCESS_SECRET` | 空 | 仅注入知乎 sidecar 的开放平台 Bearer 凭证 |
| `BILIBILI_RESEARCH_ENABLED` | `false` | 明确开启后才注册 B 站工具 |
| `DOUBAN_RESEARCH_ENABLED` | `false` | 明确开启后才注册豆瓣工具 |
| `DOMESTIC_RESEARCH_MAX_CALLS` | `4` | 单次业务 run 的三平台合计上限 |
| `DOMESTIC_RESEARCH_TIMEOUT_SECONDS` | `12` | 单次 sidecar 调用超时 |
| `DOMESTIC_RESEARCH_MAX_SOURCES` | `8` | 每次调用最大返回源数 |

所有开关默认关闭，避免开发环境无意间产生登录、平台流量或依赖安装。平台二进制、依赖版本与 MCP 实现必须锁定版本/commit，并完成许可证审查后再写入 Dockerfile。

## 7. 可观测性、降级与安全

运行轨迹只记录：`provider`、action、查询目的、结果数量、去重数量、耗时、错误码和被采用来源的标题/域名。不得记录查询全文以外的用户会话、Cookie、Cookie 路径、账号资料、完整平台响应或思维链。

| 情况 | Agent 行为 | 用户可见行为 |
| --- | --- | --- |
| 知乎凭证失效 | 不重试鉴权；降级 | 不提示账号信息；必要时仅显示“部分中文社区资料暂不可用” |
| 单平台限流/超时 | 记录失败并尝试其他合适工具 | 不阻断候选或报告 |
| 返回内容无歌曲实体对 | 仅保留为报告语境，或丢弃 | 不伪造候选歌曲 |
| URL/摘要不符合契约 | 丢弃 | 无提示或简短降级提示 |
| 所有研究工具不可用 | 继续现有 Web Search/MusicBrainz/Milvus 补充链路 | 正常输出可用结果 |

## 8. 前端展示

- 候选确认页沿用现有“探索依据”折叠区；来源域名可显示为“知乎 / B 站 / 豆瓣”，但不增加平台内容流；
- 报告推荐卡可显示简洁来源标签，例如“B 站访谈”“知乎回答”“豆瓣音乐条目”，链接以新标签页打开且带 `rel="noreferrer noopener"`；
- 小红书链接统一显示为“公开网页线索”，避免暗示系统登录或验证过笔记正文；
- SSE 只显示“正在补充中文社区音乐资料”等动作级进度，不显示问题全文、回答原文、账号、Cookie 或原始工具调用。

## 9. 分阶段实施与验收

### 阶段 A：统一契约与知乎只读适配

1. 实现 `ResearchSource` schema、URL/摘要过滤和 `DomesticContentResearchTool`；
2. 建立官方知乎 CLI sidecar 与仅搜索命令白名单；
3. 完成无凭证、失效凭证、正常 JSON 搜索三类测试。

实现记录：已实现统一 `ResearchSource` 过滤契约、默认关闭的 `DomesticContentResearchTool` 与 `zhihu-research` 内部 sidecar。知乎侧车在构建时从官方 manifest 下载并校验 SHA-256 后安装官方 `zhihu-cli`，以开放平台 Access Secret 只执行 `search zhihu`，再处理受限 JSON 投影；不再包含 Cookie 卷、二维码登录或社区 CLI。

### 阶段 B：B 站与豆瓣查询适配

1. 接入锁定版本的 B 站 MCP/REST adapter，仅开放搜索与详情；
2. 接入 `douban-cli` lookup-only HTTP adapter，明确禁用 mirror；
3. 完成限流、异常、无结果与来源去重测试。

实现记录：B 站已实现为不要求账号的公开视频检索 sidecar，仅返回标题、UP 主、简介摘要、BV 号和公开视频 URL；不读取评论、弹幕或媒体。豆瓣仍保持默认关闭，待确认稳定的 lookup-only 数据源和许可证边界后再启用，避免将不受控抓取带入主链路。

### 阶段 C：双 Agent 联调

1. 候选池 Agent 对来自平台的歌曲线索仍强制 MusicBrainz 核验；
2. 报告 Agent 能生成带平台来源标签的推荐理由；
3. 在工具均关闭时，现有候选池和报告验收用例保持通过。

验收标准：

1. 不会新增业务 Agent 或固定的跨平台调用顺序；
2. 所有启用平台仅执行白名单只读操作，知乎 Access Secret 不出现在代码库、日志、SSE、模型输入或 API 响应；
3. 平台结果均符合 `ResearchSource` 字段长度、域名与去重规则；
4. 候选歌曲只能在 MusicBrainz 核验和 Java 入库后进入主池/补位池；
5. 单个平台故障不会导致候选池或报告失败；
6. B 站、知乎、豆瓣来源在前端以可点击、简洁、非事实背书的形式展示；
7. Agent、Java、Web 自动测试及各 sidecar 的健康检查通过。
