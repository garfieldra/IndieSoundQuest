# 候选歌曲证据模型与质量控制

- 状态：已实现首版

## 目标

每首候选必须是可引用的规范目录实体，并说明发现来源、核验状态、相关理由，以及属于主池还是补位池。

## 生命周期与契约

生命周期为 `DISCOVERED -> IDENTITY_PENDING -> VERIFIED -> ELIGIBLE -> MAIN/RESERVE`；`AMBIGUOUS`、`DUPLICATE`、`VERIFICATION_FAILED`、`REJECTED` 不得进入赛事。

候选包含 `recordingId`、理由、探索依据、公开证据、`discoverySources`、`qualityDimensions`、`poolRole` 和 `verificationStatus`。质量维度分别描述偏好相关性、身份可信度、来源可信度和约束匹配，不合并为机械总分。

## 数量与策略

16 首赛事目标 32 首，32 首赛事目标 64 首；前一半为 MAIN，后一半为 RESERVE，删除后直接递补而不重新调用模型。

- 单艺人锁定：只允许该艺人及确认别名。
- 艺人作为起点：允许沿相似风格、合作、专辑与文化语境扩展。
- 无明确艺人：Agent 自主把场景、情绪、流派、语言、年代和文化语境转换成搜索切面。
- 不写死搜索顺序、艺人占比或本地/网络比例。

## 完成与展示

候选须存在于 Java 目录、通过实体和重复校验、满足明确约束并有相关性说明。只有扩大搜索、调整查询和重试后仍无法补足时才返回不足。前端显示推荐理由、平台入口和“MusicBrainz 已核验/目录已核验”，公开来源置于可展开区域；内部评分不展示。
