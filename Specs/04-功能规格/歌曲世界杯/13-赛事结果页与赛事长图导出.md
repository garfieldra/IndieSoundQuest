# 赛事结果页与赛事长图导出

> 状态：已实现并验证  
> 版本：v1.0  
> 前置规格：`01-歌曲世界杯核心闭环.md`、`08-赛后报告长图导出.md`、`12-歌曲试听与平台跳转.md`

## 1. 目标

把一场完成的“歌曲世界杯”从一句“冠军诞生”升级为完整、可回看的赛事结果页：用户能看到冠军、亚军、四强、两侧半区逐轮汇聚到中央决赛的淘汰赛图，并可预览和下载整场赛事的 PNG 长图。

本功能只服务个人回顾与保存，不加入社交关系、榜单、评论、公开分享或用户账号体系。

> 实现记录（2026-08-22）：`GET /api/v1/tournaments/{id}` 已返回 `completedAt`；前端在最后一票刷新为 `COMPLETED` 后直接切换到结果页。结果页从已有 `entries + matches(roundNumber, matchIndex)` 推导冠军、亚军、四强和冠军路线，不新增独立结果接口；赛事长图使用本地 DOM 的 1600px 固定画布生成 PNG。已用 16 / 32 首纯数据测试覆盖结果推导，并完成 Java 测试、前端测试和生产构建。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 进入时机 | 最后一票提交成功后，前端自动进入赛事结果页 |
| 赛程范围 | 展示完整 16 / 32 首淘汰赛树，并高亮冠军晋级路线 |
| 长图内容 | 冠军、亚军、赛事摘要、完整赛程树 |
| 半决赛落败者 | 标注为“四强”，不虚构第三、第四名排名 |
| 冠军卡片 | 封面、歌名、艺人、站内试听、网易云搜索入口 |
| 导出 | 与报告一致，先预览、再由用户下载 PNG |
| 二维码 | 首版不显示；导出页脚仅保留 `IndieSoundQuest` 署名和未来二维码安全留白 |
| 视觉 | 暖白唱片内页风格；淘汰赛图类似真实世界杯：左右半区从外侧逐轮向中央决赛汇聚 |

## 3. 用户体验

### 3.1 赛后路径

```text
最后一票成功
  → 自动刷新赛事详情
  → 自动进入“本场结果”
  → 查看冠军和完整赛程
  → 可试听 / 去网易云搜索
  → 预览并下载赛事长图
  → 主动生成或查看赛后偏好报告
```

结果页必须先呈现赛事本身；Agent 报告作为结果页下方的下一步入口或已生成内容，不抢占冠军和赛程的第一视觉层级。

### 3.2 页面内容顺序

1. **赛事摘要**：`{16|32} 首歌曲世界杯`、完成时间、总投票场数。
2. **冠军区**：冠军封面、歌名、艺人、`本场冠军` 标识、试听状态、Apple 归属链接（试听可用时）、网易云搜索入口。
3. **决赛对局**：冠军与亚军并列展示，明确决赛结果。
4. **四强**：两位半决赛落败歌曲，只标注“四强”。
5. **完整淘汰赛图**：桌面端双半区汇聚图；移动端轮次展开图。
6. **操作区**：`预览赛事长图`、`生成本场偏好报告` / 已生成报告入口、`再办一场`。
7. **报告区**：沿用现有赛后偏好报告与报告长图功能。

## 4. 世界杯式赛程图

### 4.1 桌面端：双半区向中央汇聚

```text
左半区（从左向中）                         中央                         右半区（从右向中）

第一轮 → 八强 → 四强 ──┐              ┌── 四强 ← 八强 ← 第一轮
                       ├→ 决赛 → 冠军 ←┤
第一轮 → 八强 → 四强 ──┘              └── 四强 ← 八强 ← 第一轮
```

- 左半区的轮次从左向右排列；右半区镜像，从右向左排列。
- 最后一轮的两个半决赛胜者在中央决赛相遇，冠军作为中央视觉锚点。
- 已完成的对局显示双方歌曲与胜者；冠军路线使用低饱和砖红色线条和名称强调。
- 非冠军路线保持低对比棕灰，不以大面积颜色制造噪音。
- 卡片只显示封面缩略图、歌名和艺人；长名称两行截断，完整信息由悬浮、聚焦或移动端展开获得。
- 不使用模拟足球比分、国家旗帜、奖杯 Emoji 或不属于音乐产品的体育装饰。

### 4.2 数据映射规则

- 以 `roundNumber` 和 `matchIndex` 为唯一布局依据，不根据歌曲或艺人名称推断位置。
- 每轮 `matchIndex < 本轮对局数 / 2` 的对局进入左半区，其余进入右半区。
- 后续轮次按 `floor(matchIndex / 2)` 聚合至父对局；最终轮次为中央决赛。
- 冠军路径从决赛 `winnerEntryId` 逆向追溯：某轮对局的胜者等于下一轮指定参赛者时，该对局与连线标为冠军路径。
- 亚军为决赛中非 `winnerEntryId` 的 entry。
- 四强为两场半决赛的非 `winnerEntryId` entry；首版不输出第三、第四名。

### 4.3 移动端降级

- 不横向压缩桌面赛程图。
- 以“第一轮 / 八强 / 四强 / 决赛”折叠区按时间顺序展示，每场显示胜者、对手和冠军路径标识。
- 冠军、亚军与四强仍固定在折叠区之前。
- 导出图不使用移动端布局，始终渲染固定宽度的完整双半区赛程图。

## 5. 赛事长图

### 5.1 技术方案

- 完全由浏览器本地通过现有 `html-to-image` 的 `toPng` 生成；不新增上传、截图服务或 Agent 调用。
- 新建屏幕外 `.tournament-export` DOM 容器，固定宽度 `1600px`、暖白背景、`pixelRatio: 2`。
- 导出内容依次为：赛事摘要、冠军与亚军、四强、完整双半区赛程图、页脚署名与二维码留白。
- 长图加载封面时遵循现有降级：跨域失败、缺失或超时均显示 CSS 唱片标签，不阻断导出。
- 生成后展示模态预览；用户主动点击后才下载，文件名为 `indie-sound-quest-tournament-{tournamentId-short}.png`。
- 任何 UUID 只用于文件内部生成，不展示在页面或图片中。

### 5.2 视觉规则

- 延续“暖白唱片内页感”：`#fdf9f4` 背景、宋体标题、无衬线正文、细棕灰分隔线、砖红仅用于冠军路径与操作重点。
- 中央冠军封面最大，左右赛程密度递减但保持清晰可读。
- 赛程连接线使用 CSS/SVG 的可序列化元素；不得采用 Canvas，保证 `html-to-image` 输出稳定。
- 页脚不放二维码图案；保留克制的留白区域，以便正式域名确定后再单独增加二维码功能。

## 6. 后端与接口

现有 `GET /api/v1/tournaments/{id}` 已返回 entries、matches、completedVoteCount 和状态，足以构建赛程主体。

需要扩展：

| 字段 | 用途 |
| --- | --- |
| `completedAt` | 结果页与长图显示完成时间 |

不新增赛事结果专用接口、不新增 Python Agent 工作流、不改动投票事务。冠军、亚军、四强与冠军路径都由前端从已校验的赛事事实快照推导。

## 7. 试听与外链

- 结果页冠军、亚军和四强歌曲卡复用 `GET /api/v1/recordings/{recordingId}/listening-options`。
- 点击歌曲卡片只控制试听；网易云搜索在独立链接中打开。
- 结果长图不嵌入试听音频、外部 URL、Apple 商标或二维码；长图中只保留歌曲与艺人文本。
- 不记录结果页试听行为，不更新偏好档案，也不输入 Agent。

## 8. 可访问性与异常处理

- 结果页提供可读的冠军、亚军、四强和按轮次文本结构，赛程图不作为唯一信息载体。
- 所有歌曲卡、导出、报告生成和“再办一场”均可键盘访问。
- 赛事详情加载失败时显示重试按钮；长图失败时结果页仍可正常浏览。
- 赛事尚未完成时不显示结果页和长图入口。
- 连续点击导出按钮只允许一个本地生成任务。

## 9. 非目标

- 不做公开分享、社交动态、排行榜、评论或他人赛事查看；
- 不做季军赛，也不计算第三、第四名；
- 不改造赛事为双败赛制；
- 不持久化 PNG 文件；
- 不在本功能中实现访客历史、账号登录或跨设备同步；
- 不暴露模型推理过程、Prompt、内部工具调用或访客标识。

## 10. 验收标准

- [ ] 最后一票成功后自动进入结果页，冠军歌曲正确显示；
- [ ] 16 首与 32 首赛事均可得到冠军、亚军和两位四强；
- [ ] 桌面端赛程图呈左右半区向中央冠军汇聚的结构；
- [ ] 冠军路径与非冠军路径可清晰区分；
- [ ] 移动端按轮次展开，不出现不可读的横向缩放赛程图；
- [ ] 冠军卡可试听，并有网易云搜索入口；
- [ ] 赛事长图包含完整赛程、冠军、亚军、四强和赛事摘要；
- [ ] 无封面或跨域封面失败时长图仍可生成；
- [ ] 生成赛事长图不会新增后端写入、Agent 调用或用户数据外传；
- [ ] 既有报告生成、报告长图和“再办一场”流程不回归。
