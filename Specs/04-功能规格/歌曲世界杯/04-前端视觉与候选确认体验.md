# 前端视觉与候选确认体验

**状态：** 开发中 v0.1  
**最后更新：** 2026-08-03  
**关联：** `03-Agent候选池确认与开赛.md`（交互、状态、接口与验收以该 v1.0 规格为准；本文只补充视觉约束）

## 目标

以“暖白唱片内页”为唯一默认主题，完成偏好探索候选池的生成、补位确认与开赛页面。页面应安静、精致、以专辑封面和排版为主体，不呈现聊天机器人或模板化 AI 页面。

## 视觉系统

| 要素 | 规则 |
| --- | --- |
| 底色 | 暖白 `#f5f0e8`，纸张层 `#fffdfa`，深墨 `#26211d` |
| 强调 | 栗红 `#9c493a`，仅用于主操作、进度和焦点 |
| 字体 | 标题 `Songti SC, STSong, Noto Serif SC, serif`；正文 `PingFang SC, Helvetica Neue, sans-serif` |
| 形状 | 轻圆角、1px 细线、极弱阴影；不使用玻璃拟态或大面积渐变 |
| 图形 | 只用文字、细线与封面；不使用 emoji、拟人插画或 AI 聊天气泡 |

## 页面流程

1. 首页顶部提供“代表作直接开赛 / 按偏好探索”切换。
2. 探索表单：偏好文本、可选起点艺人、16/32 首规模。
3. 生成后，以唱片目录式网格展示正式候选；候补不直接呈现。
4. 移除一首时，下一首候补以简短淡入补位；已移除列表可恢复该歌曲。
5. 点击“以这组歌曲开赛”后创建 `AGENT_GENERATED` 赛事并进入既有对局页。

## 组件与状态

- `ExploreForm`：请求 `/candidate-pools`；请求中禁止重复提交。
- `CandidateShelf`：只保存完整有序 `items` 与 `excludedIds`；active、reserve、removed 均按父规格的确定性算法派生。
- `CandidateCard`：封面、歌名、艺人、专辑、理由；无封面时使用唱片标签式占位。
- `RemovedList`：只在有已移除歌曲时出现，不默认占据页面空间。
- 所有接口使用 Cookie；不保存模型输出、Cookie 或密钥到 localStorage。

## 响应式与可访问性

- 宽屏候选网格最多四列，窄屏两列；正文最小 16px。
- 操作按钮有可见焦点和文字标签；封面有替代文本。
- 状态信息使用 `aria-live`，不能只用颜色传达补位和错误。

## 验收

- [ ] 页面无 emoji、渐变 hero、玻璃卡片和聊天气泡；
- [ ] 16/32 两种规模都能生成并显示正式候选；
- [ ] 移除后无需重新请求即可补位，恢复后顺序可逆；
- [ ] 候补耗尽时禁用移除，不影响开赛；
- [ ] 成功开赛后进入已有世界杯对局。
