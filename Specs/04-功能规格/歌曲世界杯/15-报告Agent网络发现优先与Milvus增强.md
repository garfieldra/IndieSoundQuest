# 报告 Agent：网络发现优先与 Milvus 增强

> 状态：已实现（真实 ReAct 联调完成）  
> 依赖：`07-报告Agent子Agent与证据链.md`、`10-歌词派生主题卡与双层知识库.md`

## 1. 目标

在不新增第三个业务 Agent 的前提下，扩展现有赛后报告 ReAct Agent：它可自主使用网络研究与 Milvus 主题知识，但两者有明确、不可倒置的职责。

报告要同时提供：

- 基于本场比赛事实的偏好解释；
- 来自公开网络发现的跨艺人歌曲、艺人推荐；
- 由本地主题卡补强的“为什么这些方向与你本场选择相连”的解释；
- 面向前端的简洁“探索依据”标签，不泄露内部检索分数、原始摘要或模型轨迹。

## 2. 关键定位与强约束

### 2.1 网络发现是推荐主体

- `search_web` / 网络研究子 Agent 是跨艺人新歌曲、新艺人的**主发现来源**。
- 网络发现项必须保留来源 URL、来源标题和搜索关键词；未导入本地目录时以 `web_discovered` 展示，不能伪装成已验证实体。
- 推荐不能因为 Milvus 中没有相似主题卡而被限制、拒绝或降级；网络发现与 MusicBrainz/Java 实体核验仍是主体链路。

### 2.2 Milvus 仅是增强层

- `search_knowledge` 的输入仅包含赛事胜者、偏好信号和用户可见的主题方向；它只读取已审核 `LOCAL_CURATED` 主题卡。
- 结果只可用于补充偏好维度说明、推荐理由和前端主题标签；不得单独作为外部歌曲/艺人的真实性来源。
- Milvus 不可用、空结果、检索较弱时，报告与网络发现必须照常完成，并写入可观测的降级摘要而非用户错误。
- 不传递、不显示、不写入歌词原文、源文件路径、向量、相似度分数或内部 Claim ID。

## 3. ReAct 行动与决策

主 Agent 动作白名单扩充为：

```text
analyze_tournament
search_web
search_knowledge
draft_report
critique_report
submit_report
finish_degraded
```

Agent 根据黑板自主决定是否调用两个检索工具，常见但非固定的策略是：先分析本场信号；若需要跨艺人新发现则优先网络研究；在需要解释主题关联或扩展推荐理由时再检索 Milvus。运行时只保留“提交前必须有草稿和审查”的质量护栏，不把工具顺序写死。

## 4. 黑板与工具契约

新增黑板字段：

| 字段 | 内容 | 用途 |
| --- | --- | --- |
| `network_sources` | 网络研究的受限来源 | 主推荐发现与可展示外链 |
| `knowledge_context` | 至多 6 条主题卡的歌名、艺人、主题、情绪、场景、概述 | 解释与理由增强 |
| `knowledge_tags` | 去重后的短主题标签 | 前端“探索依据” |

`search_knowledge` 不接收、也不返回原始歌词。查询文本由赛事冠军、胜者分布和已归纳的偏好信号组成；工具失败返回空数组，主 Agent 自主继续。

## 5. 输出与前端

- 偏好维度和推荐理由可引用 `knowledge` 软证据，但每个偏好维度仍需保留至少一条 `match`/`vote` 硬证据。
- 推荐卡沿用现有 `catalog_verified` / `web_discovered` 分型；网络发现优先占据跨艺人推荐位置。
- 报告页可在“探索依据”中展示 2–5 个短标签，例如“都市孤独”“深夜独处”，不展示分数、原始摘要、工具调用或内部 ID。
- 长图导出复用同一可见标签；不新增内部诊断信息。

## 6. 验收

- [x] 网络可用时，跨艺人报告至少尝试一次网络研究；网络发现可进入推荐卡且保留来源；
- [ ] Milvus 命中仅增强解释，删除/清空 Milvus 后网络推荐仍可生成；
- [x] 报告 ReAct 可在一次真实任务中自主选择 `search_knowledge`；
- [ ] 前端只展示受控主题标签与可见推荐理由；
- [ ] 无原始歌词、源路径、相似度、内部 ID 或思维链进入 API、页面、长图或日志。

联调脚本：`Demos/verify_report_agent_knowledge_integration.py`。它运行真实报告图并只输出行动、来源类型、主题标签数量等受控摘要。
