# 香港轻量服务器生产部署规格

**状态：** 实施中  
**目标环境：** 腾讯云 Lighthouse（香港，Ubuntu 24.04，2C/8G/80G）  
**适用范围：** IndieSoundQuest 的求职演示部署，不含账号系统和高可用集群。

## 1. 目标

将本地 Docker Compose 开发环境转换为一个可经域名访问的 HTTPS 网站，同时保持音乐数据、服务令牌与模型密钥不暴露给浏览器或公网。

## 2. 拓扑与暴露面

```text
浏览器 -- HTTPS :443 --> Caddy（静态 React + /api 反向代理） --> Java REST API
                                                              --> Python Agent
Java / Agent --> MySQL、Redis、Milvus（仅 Docker 内部网络）
Java / Agent --> DeepSeek、Tavily、MusicBrainz、Apple（仅出站访问）
```

- 宿主机只发布 `80`、`443`；部署期间临时保留 `22` 用于 SSH 管理。
- MySQL、Redis、Milvus、etcd、MinIO、Java 与 Agent 不发布宿主机端口。
- `web` 采用多阶段构建：Vite 产物由 Caddy 提供；同域 `/api/*` 反代至 Java，因此无需浏览器跨域配置。
- Caddy 对域名自动签发和续期 HTTPS 证书，`/data` 和 `/config` 使用持久卷。

## 3. 文件与密钥

- `infra/compose.production.yaml`：独立生产 Compose，不覆盖本地开发 Compose。
- `web/Dockerfile.production`、`web/Caddyfile`：静态构建与统一 HTTPS 入口。
- `.env.production`：仅存在服务器，权限为 `600`，绝不提交 Git。
- `.env.production.example`：可提交的变量清单，不含真实值。

所有此前在开发过程中出现过的模型或搜索服务密钥都应重新生成后写入生产 `.env.production`；不得写进镜像、仓库、日志或前端构建产物。

## 4. 服务器防火墙

| 端口 | 用途 | 来源 |
| --- | --- | --- |
| TCP 22 | SSH 管理 | 部署期间可临时全部 IPv4；完成后收紧为维护者公网 IP |
| TCP 80 | HTTP → HTTPS 证书校验与跳转 | 全部 IPv4 |
| TCP 443 | 网站 HTTPS | 全部 IPv4 |

不得开放 `5173`、`8080`、`8000`、`3306`、`6379`、`19530`、`2379`、`9000`。

## 5. 发布顺序

1. 配置域名 A 记录到实例公网 IP，并等待解析生效；
2. 将本仓库推送至 GitHub 后，由服务器克隆；
3. 服务器创建 `.env.production`，填写新生成的生产密钥；
4. 通过 `docker compose --env-file .env.production -f infra/compose.production.yaml up -d --build` 发布；
5. 检查 Java 健康状态、Caddy 日志、候选池生成、投票、报告和试听；
6. 将 SSH 22 端口来源收紧，并建立 MySQL 定期备份。
